# Soundness audit in tests: the four proof systems

This is a self-audit written as executable tests, in the way an external review of a proof system would
start: try to build a false statement that verifies, and record what happened. It is **not** an independent
audit. Section 8 lists what only an external review of the AIR design and the security argument can still
establish.

It covers four packages:

| Package | Proof system | What is proven |
|---|---|---|
| `stark-pca` | Winterfell STARK, 128-bit field, BLAKE3 | the PCA release gate (fixed-point risk, budget, predicate and caveat bits, witness commitment) |
| `stark-pca-plonky3` | Plonky3 STARK, Goldilocks with a degree-2 challenge field, Poseidon2 | the same release gate |
| `pca-folding-ivc` | Nova folding (Pallas/Vesta, IPA, Spartan) | an action history: hash chain and cumulative budget |
| `pca-zkvm` | RISC Zero guest (succinct and Groth16 receipts) | the full release decision, including the Ed25519 capability chain |

Run it: `cargo test --release` in each crate (the zkVM crates are `-p pca-zkvm-core` and `-p pca-zkvm-verify`).
The longer fuzz budgets are opt-in: `STARK_FUZZ_SECS`, `PL3_FUZZ_SECS`, `FOLD_FUZZ_SECS`.

| Constraint mutation: STARK (Winterfell) | 88 transition constraints and 22 boundary assertions: every one is either killed by a witness that violates the intended relation, or classified (implied by the others, or carries no statement) and pinned by name |
| Constraint mutation: STARK (Plonky3) | all 110 constraints covered by 117 cases: 91 necessary, 22 redundant (no statement), 4 implied |
| Constraint mutation: Nova step circuit | 355 constraints: 314 killed, 41 redundant (one range gadget, shown equivalent) |
| Malicious-prover forgeries | 0 accepted (13 policy-rule violations per STARK, 160 trace manipulations (80 per STARK), 18,875 structured proof rewrites, 32 splice and truncation forgeries) |

| Fuzzing | no panic escapes, no mutant verifies, no hostile length makes a process abort (section 5) |

The proven figures are the honest lower bound. The conjectured figures rest on a proximity-gap conjecture
that has been under active research; do not read 110 or 127 as proven.

## 2. Method

1. **Constraint ablation.** The real constraint code is run unchanged through a wrapper that can silently drop
   one constraint (the mutant). A mutant is *killed* when some assignment that violates the intended relation
   satisfies every remaining constraint while the unmodified circuit rejects it. A constraint that no attack
   can exploit is classified: *implied* (the others already force it), *equivalent* (the ablated system only
   ever certifies true statements) or *necessary*. The classification is pinned by name in the tests, so a
   change in the circuit that turns a necessary constraint into a redundant one fails the build.
2. **Malicious provers.** Witnesses that violate each policy rule are fed to the real prover; the trace and the
   public inputs are then edited by hand; finally the structured parts of a valid proof are rewritten.
3. **Differential testing.** One seeded corpus (generated by a script from the TypeScript reference model)
   drives every system; the decision of each is compared with an exact big-integer evaluation of the relation.
4. **Fuzzing.** Structure-aware mutation of valid proofs under an allocation watchdog, plus a child-process pass
   (an allocation abort cannot be caught in-process).
5. **Parameter arithmetic.** The security level is computed from the pinned options and asserted against floors.

## 3. Findings that were fixed

1. **`stark-pca`: a hostile length prefix aborted the verifier (found by structure-aware fuzzing).** The
   proof keeps each Merkle batch opening as an opaque byte blob that Winterfell decodes only inside
   `verify`, with `Vec::with_capacity(count)` on an attacker-controlled count. A 43 KB proof (the size at audit time; now 48 KB) with one nested
   count rewritten to 2^52 made `verify_release_bytes` abort the process ("memory allocation of ... bytes
   failed"), which no `catch_unwind` can stop. The decoder now pre-validates the layout of every opening
   (trace queries, constraint queries and each FRI layer) and `verify_release` re-validates proofs that did
   not come through the decoder. Regression: `nested_count_rewrite_is_refused_at_decode_time` and the
   child-process pass `hostile_counts_never_abort_the_process`.
2. **`stark-pca`: the bounds check of the stock byte reader can wrap.** `SliceReader::check_eor` computes
   `position + num_bytes`, which overflows in release builds for a length near `usize::MAX`. The bounded
   reader now compares against the remaining length instead. Covered by the same fuzz and abort tests.
3. **`pca-zkvm`: the in-guest Ed25519 check accepted a mixed-order delegator key** that the reference
   implementation rejects (found earlier by the cross-implementation suite; the guest image id changed).
   This audit adds the evidence that the torsion check is the cause of the denial (section 6.4) and a
   torsion-R variant set.

Observations that are not defects, recorded so they are not rediscovered:

- RISC Zero's Rust Groth16 verifier accepts three seal encodings (bit 7 of bytes 32, 128 and 224: ignored flag
  bits). The points and the statement are unchanged, but a hash of the seal must not be used as a unique
  receipt identifier.
- `stark-pca-plonky3`: range check 12 (budget non-negative) is *not* implied by check 15 in Goldilocks, because
  `S*B - kappa*r_raw` can wrap modulo p for a "negative" budget; the AIR keeps check 12, and a wrapping-budget
  attack is part of the ablation suite so the check cannot be removed unnoticed.
- The Plonky3 prover builds traces from `u64`; the witness value `p` is the field element 0. The resulting
  proof is about the witness that really is 0, bound to that witness's commitment, so it is not a bypass
  (`u64_witness_equal_to_the_prime_is_the_field_element_zero_not_a_bypass`). Callers that want to refuse
  out-of-range witnesses before proving should validate them first.
- The zkVM guest clamps risk inputs into `[0, S]` and has no `bMax` range check; the TypeScript model behaves
  the same way, while both STARKs refuse such witnesses. Neither budget value is bound to an external
  authority in the zkVM journal, so the cap would not add a guarantee there.
- `stark-pca` relies on `catch_unwind` as defence in depth for residual panics inside Winterfell's decoding
  (the fuzzer provoked 41 such panics in 90 s, all contained). A build with `panic = "abort"` would turn them
  into aborts; keep the default `panic = "unwind"` for verifiers.

## 4. Constraint mutation

### 4.1 Winterfell AIR (`tests/soundness_ablation.rs`)

118 cases over 88 transition constraints and 22 boundary assertions: 87 necessary, 22 equivalent, 9 implied.

- **Necessary (87):** every remaining constraint and assertion. Each has a witness that violates the intended
  relation, which the ablated system proves and the real verifier rejects.
- **Equivalent (22):** the constant-propagation constraints evaluated on the last row, the doubling column on
  the last row, hash lanes 4 to 9 on the last row, and the two gate bits `tgate` and `bgate` (they are
  constant ones in the statement and carry no information). Ablating them only ever certifies true
  statements.
- **Implied (9):** the four boolean constraints (each is forced by `pm*co*tgate*bgate == 1` together with the
  other three), and the whole of range check 12 (forced by check 15).

### 4.2 Plonky3 AIR (`tests/soundness_ablation.rs`)

117 attack cases cover all 110 `assert_zero` calls of the real AIR: 91 necessary, 22 equivalent, 4 implied (the
four booleans). Range check 12 is necessary here (section 3). The test fails if the constraint count changes.

### 4.3 Nova step circuit (`tests/soundness_r1cs.rs`)

The real `synthesize` is recorded as 355 R1CS constraints: 33 for the cost range gadget, 238 inside the Poseidon
chain hash, 1 addition, 41 for the range gadget on the new total, 1 linking the headroom, 41 for the headroom
gadget. Each is dropped in turn.

| Family | Constraints | Killed | Attack |
|---|---|---|---|
| cost range (32 booleans, 1 decomposition) | 33 | 33 | a field-negative cost (-1 with an incoming total of 5) keeps the total in range; absorbing the discrepancy into one bit breaks only that bit's boolean constraint |
| Poseidon chain hash | 238 | 238 | free one wire, recompute everything downstream honestly: the chain output differs from the native hash while every other constraint holds |
| addition | 1 | 1 | the total is changed and both range gadgets rebuilt consistently |
| headroom link | 1 | 1 | an over-budget total with a claimed in-range headroom |
| headroom range (40 booleans, 1 decomposition) | 41 | 41 | one over the ceiling; the discrepancy is absorbed into one bit |
| new-total range (40 booleans, 1 decomposition) | 41 | 0 | none exists: redundant |

The new-total range gadget is redundant: the incoming total is at most `B_MAX` by induction (the first step is
pinned to zero by the verifier) and the cost is below 2^32, so the new total is below 2^33, inside the 40-bit
range; the headroom gadget bounds it again. Removing the whole gadget leaves accept and reject unchanged on
3,000 natural-prover witnesses (including field-negative and boundary costs). It is defence in depth, not a
weakness; the test fails if any other constraint ever stops being necessary.

Supporting checks in the same file: every auxiliary wire is pinned (10,817 single-wire edits each violate a
constraint), the constraint shape is identical for every witness, 2,082 single-step witnesses are accepted or
rejected exactly as the native replay says, and at the Nova level a field-negative cost, a cost of 2^32 and a
total one over the ceiling all fail to fold ("Relaxed R1CS is unsatisfiable"). Folding and Spartan soundness
themselves are Nova's and are not re-audited here.

## 5. Malicious provers and fuzzing

### 5.1 Witnesses that break a rule (`tests/malicious_prover.rs`, both STARKs)

13 deny witnesses for each STARK: risk over the threshold by each dimension, all dimensions
high, budget one unit under the cost, zero budget, predicate miss, caveat unsatisfied or expired, both,
inputs one above `S`, `u64::MAX`, budget one above `bMax`. None obtains a verifying proof.

Four deny rows times ten trace manipulations (set `allow`, set both bits, zero the risk column, raise the
budget column only, zero the residual accumulators, zero the range bits, forge the last-row residuals,
restart the hash chain, and more), each with the forged commitment and with the honest commitment: 80
forgeries per STARK, none accepted. A proof made under a weaker policy (lower weights, higher threshold,
zero cost scale, raised ceiling) never verifies under the real policy; a proof for one action never
verifies for another witness commitment, policy commitment or action commitment.

### 5.2 Structured proof forgery

- Winterfell: element-aligned rewrites inside every serialized section; splicing sections between two valid
  proofs.
- Plonky3: every numeric leaf of the proof's serde tree (6,049 leaves) is rewritten four ways (plus one, xor
  one, zero, and a non-canonical encoding `n + p`): 18,875 rewrites, none verifies, including the proof-of-work
  witnesses. Sections are swapped between two valid proofs (trace and quotient commitments, opened values, FRI
  commitments, openings, final polynomial, input openings), query openings and rounds are dropped or halved,
  `degree_bits` is falsified, and sibling values are duplicated: 32 forgeries, none verifies.

### 5.3 Fuzzing

| Target | Budget | Executions | Result |
|---|---|---|---|
| Winterfell decoder and verifier | 90 s + 43,136 child processes | 284,530 | no mutant verified; 41 contained internal panics; largest single allocation 86 KB; 0 abnormal exits |
| Plonky3 decoder and verifier | 90 s + 42,168 child processes | 73,921 | no mutant verified; 0 panics escaped; largest single allocation 0.87 MB; 0 abnormal exits |
| Nova compressed-proof decoder and verifier | 60 s + 3,984 child processes | 2,544 (766 decoded) | no mutant verified; 0 panics escaped; largest single allocation 1 MB; 0 abnormal exits |

Operators: bit flips, hostile length prefixes (shortest and fixed-width encodings), boundary field-element
blocks, truncation, insertion, deletion, splicing from a second valid proof, block duplication and swapping.
These are bounded runs, not coverage-guided campaigns.

## 6. Cross-implementation agreement

### 6.1 Corpus

`differential_corpus.json` holds 2,528 seeded witnesses: 1,200 random, boundary classes around the threshold
and the budget cost (deltas of -2 to +2 and exact), the corners of the cube, and 200 outside the quantisation
domain (inputs above `S`, budget above `bMax`). Each case carries the exact big-integer decision and the
TypeScript float model's decision. It is generated by a script from the TypeScript package and is reference
output, not an official vector.

### 6.2 Results

| System | Inside the domain (2,328) | Outside the domain (200) |
|---|---|---|
| Winterfell STARK | equals the exact reference on all 2,328 (1,176 allow, 1,152 deny) | all refused |
| Plonky3 STARK | equals the exact reference on all 2,328 | all refused |
| zkVM guest logic | equals the exact reference on all 2,328 once the committed grant's own `max_blast_radius` caveat is accounted for (79 cases are denied only by it) | clamped, equals the relation on the clamped inputs |
| TypeScript float model | stricter than exact at 47 exact boundaries (float rounding), never more permissive | |

### 6.3 Difference by design

Only the STARKs refuse out-of-domain witnesses; the guest and the TypeScript model clamp. The zkVM also
evaluates predicates, caveats and the capability chain, which the STARKs take as booleans.

### 6.4 Torsion in the zkVM's Ed25519 check

The variant set (52 chain cases and 13 leaf cases, verdicts from the TypeScript reference on a different
Ed25519 implementation) now contains the cases for a torsion R: R plus an order-8 point with an honest key, a
small-order R, and a mixed-order key together with a mixed-order R ground so the cofactorless equation holds.
For the last one and for the original mixed-order key, `ed25519-dalek`'s `verify_strict` alone **accepts** the
signature while the fixed guest and the reference reject it, so the torsion-freeness requirement is the cause
of the denial. With a prime-order key a torsion R can never satisfy the cofactorless equation, so the R check
cannot be isolated as the only reason for a denial; it is defence in depth. There is no RFC vector for
mixed-order keys.

The guest reports every refusal with the same panic text, so the committed negative-proving record cannot say
why. `negative_causes.rs` runs the same decision code natively: for each of the 16 variants exactly one input
group (risk and budget, action, chain, leaf PCActn, clock or delegation depth), restored to its compliant
value, turns the denial into an allow, and restoring every other group does not. The cause table is tied to
the tier, risk and chain verdict recorded in the committed run.

## 7. Security level

### 7.1 Winterfell (`stark-pca`, `tests/security_bits.rs`)

- Field: `f128`, modulus 2^128 - 45*2^40 + 1, no extension, so 128 bits of field.
- FRI: blow-up 8 gives 3 bits per query (conjectured), 37 queries give 111 bits. Grinding: 0 bits.
- Hash: BLAKE3-256, 128-bit collision resistance.
- Conjectured = min(min(128, 111) - 1, 128) = **110 bits** (matches the library's own figure).
- Proven (ePrint 2024/1553): **54 bits** in the list-decoding regime, **30 bits** in the unique-decoding regime.
- Floors asserted: 100 conjectured, 54 and 30 proven. The pinned options were raised from 32 to 37 queries
  (95 to 110 bits conjectured; proof 43,135 to 48,894 bytes, prove 2.2 to 2.7 ms, verify 0.4 to 0.8 ms), a
  breaking change: proofs made with the old options no longer verify. The verifier pins the exact options, and
  valid proofs made with 32 queries (95 bits), blow-up 4, FRI folding 4 or remainder 15 are all refused.

### 7.2 Plonky3 (`stark-pca-plonky3`, `tests/security_bits.rs`)

- Challenge field: Goldilocks squared, p^2 with log2 = 127.99999.
- Blow-up 4 (rate 1/4), 64 queries, 8 bits of query-phase grinding, Poseidon2 with a 256-bit digest.
- Conjectured: 64 * 2 + 8 = 136 bits of FRI; hash 128; field 128 minus one: 127 bits by this hand computation. CORRECTED (F-6): `p3-security` 0.8.0 reports **112-113 conjectured**, 70 proven (list-decoding radius) and 50 proven (unique decoding); use those figures (`proofs/07-stark-fri.md` section 3.2).
- Proven, Johnson regime: 64 * log2(1/sqrt(1/4)) + 8 = 64 + 8 = 72 bits by hand; `p3-security` gives **70** (F-6).
- Proven, unique decoding: floor(64 * log2(8/5)) + 8 = 43 + 8 = 51 bits by hand; `p3-security` gives **50** (F-6).
- Floors asserted: 100 conjectured, 72 and 51 proven; the test also reads the query count, FRI rounds and final
  polynomial length out of the committed proof so the arithmetic describes what is verified.

### 7.3 Nova (`pca-folding-ivc`, `tests/security_bits.rs`)

Nova has no query parameter. The terms are the discrete log on the Pallas/Vesta cycle (orders about 2^254, so
Pollard's rho costs sqrt(pi*q/4), about **2^126.8**), the sum-check and folding errors (degree times rounds
over 2^254, negligible), and the Poseidon chain hash. The Poseidon round numbers (8 full, 55 partial) are
checked against the paper's bounds for 128 bits (full rounds at least 6; 63 total against the interpolation
bound of 57). Floor asserted: 120 bits, classical adversary, random-oracle model. **Not post-quantum.**

### 7.4 zkVM

The soundness parameters of the succinct and Groth16 receipts are RISC Zero's; they were not recomputed here.
The tests pin what a verifier controls: the image id (a changed id, any single-bit change in the first or last
word, and the earlier guest's id are all refused), the verifier-parameters digest, and the claim digest.
The Groth16 wrap relies on a trusted setup for its wrapping circuit and on the pairing curve's security.

## 8. What only an external review can establish

- **The AIR design and the security argument.** Mutation shows that every constraint is needed or classified;
  it cannot show that the constraint set is *sufficient* for the intended statement, nor that the statement
  is the right one. That is a reading of the design against the specification by someone who did not write it.
- **The algebraic commitment hash.** Both STARKs bind the quantised witness with a custom algebraic hash
  (a cube S-box permutation with a fixed round count), not a standardised one. Its collision resistance is a
  heuristic; the 2^-N claims above do not cover it.
- **Conjectured versus proven soundness.** The conjectured figures depend on proximity-gap conjectures for
  Reed-Solomon codes up to capacity. The proven figures are 26 to 72 bits.
- **Composition.** The off-circuit link between the algebraic witness commitment and the SHA-256 action
  commitment, the predicate and caveat bits taken as witnesses by the STARKs, and the freshness and replay
  handling around a proof are outside the proof systems and outside these tests.
- **The vendored and upstream code.** Winterfell, Plonky3, Nova's gadgets and RISC Zero are dependencies; a
  defect there is outside the scope of these tests, and the Poseidon instance has no published test vector for
  its exact parameters (an independent reference reproduces it).
- **Side channels, implementation hardening and the trusted setup of the Groth16 wrap.**
- **Coverage-guided fuzzing at scale.** The runs above are minutes long.
