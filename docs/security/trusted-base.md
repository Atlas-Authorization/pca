# PCA verified core: the trusted base, and how far it has been shrunk

`verified-core.md` lists what the Dafny proofs establish and what they still rely on. This page is the working record of the
effort to **shrink that list**: for each trusted item, what independent evidence now backs it, what was found, and what is
still taken on faith. Nothing here is a proof; it is redundancy. "Cross-validated" means "several independently built
implementations agreed on a very large number of inputs", never "proved".

Reproduce everything with `tools/pca-trustbase/run-all.sh` on a box that has the pinned Dafny (see "Reproducing").

## 1. Proof toolchain (supply chain)

`formal/dafny/TOOLCHAIN.lock` pins the proof toolchain; `formal/dafny/verify-toolchain.sh` enforces it. `build.sh` itself is
unchanged (it only calls whatever `dafny` is on `PATH`), so the pin is a separate, mandatory pre-step.

| Item | Pin |
|---|---|
| Dafny | 4.11.0, commit `fcb2042d6d043a2634f0854338c08feeaaaf4ae2`, release asset `dafny-4.11.0-x64-ubuntu-22.04.zip` sha256 `a46a9ff7...e8267179` (equal to the digest GitHub publishes for the asset; checked against two sources) |
| Whole unpacked tree | 290 files, tree sha256 `c58e71fb...bd2ca7` (any extra, missing or modified file fails) |
| Z3 | 4.12.1 binary sha256 `22214e51...287eff` (the default prover for all proofs); the bundled 4.14.1 is also hash-pinned but unused |
| Boogie | 3.5.5 (from `Dafny.deps.json`), plus sha256 of `Boogie.Core/ExecutionEngine/VCGeneration/Provers.SMTLib` and `Dafny/DafnyCore/DafnyPipeline/DafnyDriver/DafnyRuntime.dll`, `DafnyPrelude.bpl`, `DafnyRuntime.jar` |
| Host | .NET 8 runtime (recorded 8.0.31); Ubuntu 24.04 x86_64 |

`verify-toolchain.sh --install` downloads the pinned zip and verifies its sha256 **before unpacking**; a tampered install is
rejected (self-tested: one appended byte in `DafnyPrelude.bpl` changes the tree hash and the script exits non-zero). It also
repeats the "no `assume`, `{:axiom}`, `extern` in the Dafny sources" audit.

Reproducibility evidence (box cloud-box-9, pinned toolchain):

* `build.sh --verify-only`: **171 verified, 0 errors**. `GlueContract.dfy` (below) with the core included: 174 verified, 0 errors (re-run 2026-10-12; the earlier 170 / 173 predate the `PqPkMismatchNeverCounts` lemma).
* `build.sh --check`: the committed `packages/pca-verified-core/generated/pca_core.js` is **byte-identical** to a fresh compile.
* `dafny translate` run twice per target is deterministic for js, go, java and python; for C# the only difference is the
  `-o` path echoed in a header comment.

SBOM: `tools/pca-trustbase/sbom/pca-verified-core.cdx.json` (CycloneDX 1.5, deterministic, regenerated by
`node tools/pca-trustbase/gen-sbom.mjs`, freshness enforced by `--check` in CI). It lists the one runtime dependency
(`bignumber.js` 9.3.1, lockfile sha512), the sha256 of the shipped generated JS and of each proved `.dfy`, the primitive
libraries the glue trusts (`@noble/curves` 1.9.1, `@noble/hashes` 1.8.0, `@noble/post-quantum` 0.4.1) and the build-time
toolchain with the hashes above. Dev dependencies are present with scope `excluded`.

What the pin does **not** do: it does not make the distro `.NET` runtime, the host OS, or the Go/Java/Python/Node runtimes
byte-pinned (their versions are recorded, `.NET` major is enforced); `goimports` (needed by Dafny's Go backend) is pinned by
version (`v0.24.0`) not by hash.

## 2. Diverse compilation: Dafny compiler and runtime (translation validation)

`formal/dafny/difftargets/Harness.dfy` includes the six proved modules **unchanged** and exposes 22 entry-point families:
every per-check decision in `Verdict.dfy` (audience, validity, version, grant-ref, counter, suite policy, PQ binding and
resolution, leaf, cap-chain, hook, plan, beacon, reversibility, threshold rule), the `CoreState` and `VerdictState` folds,
`Enforce`/`Finalize`/`WithDeniedFallback`, `Caveats` (`Allows`, `EffExpiry`), `VerifyChain`, threshold `Verify`, the replay
guard (`Pre`, `NonceStage`, `RetainUntil`, `Decide`) and the replay-store model (`ConsumeOnce`, `Prune`, `AdvanceCounter`). It is built
with `--no-verify`; the *proofs* are those of the included modules.

It is compiled with the pinned Dafny to **C#/.NET 8, Go 1.22, Java 21, Python 3.12 and JavaScript (Node 24)** and each binary is run
over the same case file. A case is a line of ints/bools (the facts and closure results the glue would produce); the result is one
canonical line. The **production side** is `packages/pca-verified-core/src/*.ts` (the typed bridge the shipped verifier calls)
over the committed `generated/pca_core.js`, driven through `test/diverse/prod-runner.ts`. All six transcripts must be
byte-identical.

| Evidence | Size | Result |
|---|---|---|
| Seeded random campaign (`gen-cases.mjs`, 22 ops, biased to boundaries; half the chunks inject integers beyond 2^53 and up to 2^128, which exercises each target's big-integer emulation) | **6,000,000 cases** x (cs, go, java, py, js + production bridge) | **0 divergences** among the five compiled targets and the bridge, after the single known bridge precision issue below |
| Production-recorded corpus (`record-corpus.test.ts`): the 3,221 decodable conformance vectors + 1,278 parse-rejects run through `verifyPCActn`/`verifyPCActnCore`, every call into the verified core captured with lazy closures evaluated | **71,966 calls** (7,228 chain walks, 12,446 PQ-binding, 10,032 suite-policy, 3,750 leaf, ...) | identical in all six |
| Pinned smoke corpus (`golden.json`, 60,000 cases) | sha256 of the transcript is committed | `test/diverse/golden.test.ts` makes a plain `pnpm test` fail if the shipped JS drifts from the 5-target consensus |
| Miscompile self-test (`selftest.sh`) | one injected off-by-one in compiled `ValidityDecision` | detected (37 differing lines): the harness is able to see a miscompile |

Wiring: `.github/workflows/pca-diverse-core.yml` is a **new, separate workflow**. It installs the hash-pinned Dafny, builds all five targets,
requires each transcript to equal the golden digest, and runs the self-test and the SBOM freshness check. It adds C#/Go/Java
(and Python/JS) as extra differential participants beside the existing `pca-conformance.yml`; no native verifier code or its
CI job was modified.

Not done: Dafny's Rust backend was not tried (no Rust toolchain on the leased box); C++ and other experimental backends are not
supported by this Dafny release for these modules.

### Divergences found

1. **FIXED: `replayRetainUntil` in the typed bridge was lossy above 2^53.** `exp + skew` can leave the safe range; the bridge now computes it exactly (`replayRetainUntilExact`, bigint) and `replayRetainUntil` throws a `RangeError` instead of returning a rounded number. The cross-check driver no longer has a KNOWN-DIVERGENCE case: it compares the bridge's exact value with every target and checks the number API throws exactly when the sum exceeds 2^53-1. Regression: `test/replay-retain-precision.test.ts` (repro `rp 1 1 1 1 1 1 9007199254729192 9007199254730192 9007199254740000 60001 0 1 0 0 1 1 0`). `guardPCActnReplay` (`packages/pca/src/replay.ts`) now also refuses, before any store call, a PCActn whose `exp + skew` exceeds 2^53-1 (code `malformed`), since the store contract takes a JS number; regression `packages/pca/src/replay-retention-range.test.ts`.
2. **No Dafny compiler or runtime divergence was found** on any target, including the big-integer paths.
3. Harness-vs-bridge normalisation (not a bug): the bridge zeroes `iat/exp/now` when the matching `*Ok` flag is false; the core
   never reads them in that case. The generator now emits the same normalised facts.

### Limits of the diverse-compilation evidence

* It validates *translation*: that five independent code generators plus their five runtimes (BigInteger, `big.Int`, `BigInteger`,
  Python `int`, `bignumber.js`) implement the same function on the sampled inputs. It does **not** validate Dafny's front end, Boogie or Z3,
  which are shared by all targets. A soundness bug in the verifier would be invisible here.
* Four of the five targets share Dafny's AST and its type-erasure/closure strategy; a front-end bug that mis-lowers a construct
  the same way everywhere would pass. Millions of cases reduce the chance of a *per-backend* bug, not of a *common* one.
* The campaign samples; it is not exhaustive. Boundary values (60000/60001, 3600000/3600001, 2^53 +/- 1, 2^64, 2^127) are over-represented on purpose.

## 3. The glue contract

`formal/dafny/GlueContract.dfy` (a new module; it includes the proved modules and edits none of them) states the contract as
preconditions on the booleans and proves what follows:

* `ChainAcceptedMeansRealDelegation`: if each hop's `sig()` / `parentLinkOk()` / `issuerIsParentHolder()` is *sound* (true only
  when the signature verifies under the root issuer or the parent's holder, the parent digest matches, the issuer is the parent's
  holder), then an accepted chain really is a delegation chain: every signature valid, every link and issuer correct.
  `ChainGlueExact` states the converse half for completeness.
* `LeafPassMeansValidSignature`: a leaf `LeafPass` implies a really valid leaf signature.
* `ThresholdCountedKeysHaveValidSignatures` (with `FoldBacked`): every key the accepted threshold verdict counts belongs to a
  well-formed share whose `sigOk()` held, or is the baseline agent key whose `leafSigOk()` held; with the `ShareSigContract` this means at
  least `t` really valid distinct signers. Combined with `ThresholdSound` (distinct roles).
* `ReplayFactsContract` and `PreNoneImpliesWellFormedWindow`: the `*Ok` flags must mean "safe integer" (and the skew is floored and
  clamped to 0..60000); `RetainUntilCanLeaveSafeRange` records the precision gap in 3.1.

Primitive behaviour enters only as an arbitrary relation (`World.sigValid`), so the theorems hold for *any* behaviour of the
signature primitives. They say nothing about whether a library implements the relation; that is Section 4.

The full per-boolean list (what each glue boolean must mean, where it is computed) is `tools/pca-trustbase/glue/glue-contract.json`.

## 4. Primitives: N-version comparison

`tools/pca-trustbase/primitives/run.mjs` compares independent implementations on official vectors and on random and adversarial
inputs. Voters: noble (`zip215:false`, as production uses it, and default mode), the real `pca` wrappers (`keys.ts`, `pq.ts`),
node:crypto/OpenSSL 3.5 (also ML-DSA and SLH-DSA), ed25519-dalek 2 (plain and `verify_strict`) with RustCrypto sha2/sha3/hmac and the
`fips204` crate, the `slh-dsa` crate, Go `crypto/ed25519`, PyNaCl (libsodium), Python `cryptography`, Python hashlib.

| Primitive | Evidence | Divergences |
|---|---|---|
| SHA-256/384/512, SHA3-256/512, SHAKE128/256, HMAC-SHA256/512 | NIST ACVP AFT (~2,600 tests), Wycheproof HMAC (348), boundary lengths 0..1 MiB, **1,100,000 random cases** | 0 |
| Ed25519 | Wycheproof (151), RFC 8032, 2,000 sign/derive keys over 7 voters, **150,000 random+mutated verifies over 10 voters**, a 10,500-case adversarial set (small-order A/R incl. non-canonical encodings, S >= L, y >= p, negative zero, off-curve, mixed-order via torsion, bad lengths) | classified below; **0 invalid accepted and 0 valid rejected by the production configuration** |
| ML-DSA-65/87 | ACVP keyGen and sigVer, keygen byte-equal, deterministic signatures byte-equal, cross-verify, 3,100 tampered verifies per voter per level, 4 voters | 0 |
| SLH-DSA-SHA2-128f/256s | ACVP keyGen and sigVer, deterministic signatures byte-equal, 516 and 86 verifies per voter, 4 voters | 0 |

Ed25519 divergence classes (none is a bug; none changes a production verdict):

* noble `zip215:false` alone is **cofactored**: it accepts mixed-order A/R signatures that every other library rejects. Production
  closes this: `packages/pca/src/keys.ts` `verify()` additionally rejects small-order and non-torsion-free A and R.
* The production verifier is **stricter than RFC 8032 cofactorless** for mixed-order A whose `k = 0 mod 8`: the signature is valid
  under the plain equation and every other voter accepts it; `pca-prod` rejects. Only an attacker-chosen mixed-order key is affected (honest keys
  are prime-order). Consequence: a native verifier built on a plain RFC 8032 library (Go stdlib, dalek) could accept an artifact the TS verifier
  rejects. The conformance corpus is the guard for that; it is a cross-language consistency risk, not a forgery risk.
* 16 small-order A/R cases are accepted by dalek (non-strict), Go and `cryptography`, rejected by libsodium, dalek-strict, OpenSSL and `pca-prod`
  (RFC 8032 allows both).
* `frost.ts` calls `ed25519.verify(..., {zip215:false})` without the torsion checks, only to re-check an aggregate it just produced; not a verifier path.

## 5. Glue runtime contract-checking

`packages/pca-verified-core/test/diverse/glue/**` wraps the primitive boundary (`keys.ts`, `pq.ts`, `hash.ts`, noble SHA-2) with
`vi.mock`, no production edits, and recomputes every call independently: Ed25519 with a BigInt curve model plus the OpenSSL
equation, ML-DSA/SLH-DSA with OpenSSL 3.5, SHA-2 with node:crypto, canonical JSON with a second canonicalizer, base64url with a
second strict decoder. Planted faults are caught (self-test). Result of the latest large run (3 shards, GLUE_N=100000):
**0 violations** over 7,563,749 base64url decisions, 655,151 `hashCanonical` and 315,393 `canonicalizeStrict` calls, 1,172,272 SHA-256 calls,
458,136 `verifyWithSuite` calls (10 suites plus unknown-alg and wrong-type mutations), 208,815 `verifyLeafSuite`, 1,231,508 Ed25519 fuzz
cases and the 3,222 corpus vectors per shard. A later full rerun at N=20000 (all 7 tests, threshold included) also had 0 violations.
The contract itself (5 primitive assumptions, 19 booleans, where each is computed) is `tools/pca-trustbase/glue/glue-contract.json`;
Section 3 mirrors its core part in Dafny.

## 6. What is still trusted (honest list)

1. **Dafny front end, Boogie and Z3** (shared by every compile target): a soundness bug there is invisible to diverse compilation. Mitigated
   only by the hash pin, the absence of `assume`/`axiom`/`extern`, and Dafny/Z3 being widely used; not independently re-checked (no second prover).
2. **Common-mode compiler bugs**: all five backends lower the same AST; a bug lowering one construct identically everywhere passes. The
   evidence is sampling (6M + 72k + 60k cases), not exhaustive.
3. **The glue is checked, not proved.** The Dafny `GlueContract` states and uses the contract; it cannot prove the TypeScript meets it. The runtime monitor
   recomputes 8 families of booleans independently (above) but the following have **no independent recompute**: replay-fact shape predicates, `issuerIsParentHolder`
   (pure string equality), `hookTInt`, Merkle plan-root folding and inclusion (only SHA-256 beneath is checked), hook results (caller-supplied trusted
   components), and the replay-store atomicity assumptions (TLA model only).
4. **The primitives are cross-checked, not proved.** Ed25519, SHA-2/3, HMAC, ML-DSA and SLH-DSA agree across 4 to 10 independent implementations
   on official and random vectors, but a shared specification misreading or a bug present in all implementations would pass. SLH-DSA signing samples are
   small (12 and 2 signatures). FN-DSA, LESS, HKDF, X25519, ML-KEM were not cross-checked. Collision resistance and canonicalization injectivity (`EqSound`) remain assumptions.
5. **The production Ed25519 profile is stricter than RFC 8032**; native verifiers must match it (conformance corpus), see Section 4.
6. **Bridge precision**: fixed (Section 2, item 1).
7. **V8/Node, `bignumber.js`**, the host OS, the distro .NET/Go/Java/Python runtimes, `goimports` (version-pinned only), clock integrity, and the real
   replay stores are unchanged from `verified-core.md`.
8. **Not shrunk at all**: parsing and wire validation, the Policy VM, freshness/attestation/ZK/bond verification, cryptographic security of any primitive, side channels.

## 7. Reproducing

```bash
# box with 4+ cores, .NET 8, Go, Java 21, Python 3, Node 22+
formal/dafny/verify-toolchain.sh --install --dir /work/tools/dafny --runtimes
DAFNY_DIR=/work/tools/dafny TSX=$(which tsx) tools/pca-trustbase/run-all.sh     # pin, proofs, glue-contract proofs, JS reproducibility, 5 targets + golden + self-test, SBOM
CAMPAIGN=24 DAFNY_DIR=/work/tools/dafny tools/pca-trustbase/run-all.sh          # + 6,000,000-case campaign
formal/dafny/difftargets/crosscheck.sh /work/difft some.cases                    # compare all targets + bridge on any case file
PCA_RECORD_OUT=corpus.cases pnpm --filter @atlasauth/pca-verified-core exec vitest run test/diverse/record-corpus.test.ts
```
