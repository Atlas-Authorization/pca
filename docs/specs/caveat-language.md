# Caveat language v2 (track K1)

Status: implemented in the TypeScript reference and every native verifier; security contract C-220 to C-229; threats T-320 to T-329. Source of truth for behaviour: `packages/pca/src/caveat-lang.ts`; shared vectors: `packages/pca/conformance/caveat-lang-vectors.json` (generated by `scripts/gen-conformance-k1.mjs`).

Everything here is a restriction. A caveat only removes authority, every one is conjunctive with the rest of the chain, and a verifier that does not know a type refuses the chain (unknown types are unsatisfied). No feature adds a way to widen a grant, and none makes the verifier call a third party.

## 1. Third-party caveats and discharges

`{type:"needs_discharge", id, issuer, issuer_class, bind, ttl_ms, require[], issuer_spiffe?}`

| member | rule |
|---|---|
| `id` | `^[a-z0-9][a-z0-9_.-]{0,63}$`, unique among the chain's `needs_discharge` caveats (a duplicate fails every caveat sharing it) |
| `issuer` | a **label** the verifier maps to a pin. The token never names a key |
| `issuer_class` | `human`, `org`, `workload`, `model` or `artifact` (an attestation verifier that checked build provenance, track K9: specs/supply-chain-and-guards.md); must equal the pin's class, so a model key can never satisfy a caveat that asks for a human and no other key can stand in for an artifact verifier |
| `bind` | `chain_hop`: reusable until `not_after`, revocable. `action`: one PCActn |
| `ttl_ms` | 1..86 400 000, the longest accepted `not_after - iat` |
| `require` | at most 16 `{claim, op, value}`, ops `eq neq gte lte in`; `gte`/`lte` need safe integers; `in` 1..16 scalars; every requirement must hold, an absent claim fails |
| `issuer_spiffe` | optional SPIFFE ID the pin must carry (section 6) |

A **discharge** is a signed artifact (domain `atlas-pca/discharge/v1\0`, the same signing rules as every W-B artifact: suite members `alg`/`pq_pk`/`pq_sig`, key from the verifier's pin only, post-quantum key only if it equals the pin's `pq_pk`):

`{v:1, kind:"pca-discharge", caveat_id, issuer, cap_hash, bind, action_digest?, claims, iat, not_after, nonce, sig}`

`claims` has at most 16 scalar members (string up to 256 bytes, boolean, safe integer). `nonce` is at least 16 random bytes. A discharge lives at most 24 h.

Verification order (each failure is a distinct reason): caveat well-formed; discharge well-formed; same caveat id; same issuer label; the label is pinned exactly once; pin class equals `issuer_class`; pin SPIFFE ID equals `issuer_spiffe`; signature under the pin; `bind` equal; `cap_hash` equals the hash of the hop that introduced the caveat; for `action`, `action_digest` equals the verifier's own digest of the PCActn; `iat <= now <= not_after`; `not_after - iat <= ttl_ms`; digest not on the revocation list; claims satisfy `require`.

**Freshness.** Both ends inclusive. A non-integer verifier clock refuses.
**Binding.** `cap_hash` is `capHash` of the hop that introduced the caveat (the first hop whose caveat list is longer than the caveat's position). A discharge for a child hop is useless on the parent and for another grant. For `action`, the digest is `b64u(sha256(canonical({d:"atlas-pca/discharge-action/v1", pcactn})))`, covering the counter and signature; the replay counter that admits the PCActn therefore spends the discharge. The verifier computes the digest itself and ignores any caller-supplied one.
**Replay.** `action` discharges: one PCActn once. `chain_hop` discharges: until `not_after` or until the verifier lists `discharge_digest = b64u(sha256(canonical({d:"atlas-pca/discharge-ref/v1", discharge})))` as revoked.
**Polarity.** A needs_discharge caveat is a restriction, so a model or oracle issuer can add friction but cannot grant anything. Class pinning keeps the issuer class honest.
**Offline.** The verifier never contacts the issuer. The holder fetches the discharge (a `pca-discharge-request` lists issuer, hop, binding and requirements: `dischargeRequests()`), and presents it with the action: headers `PCA-Discharges` (base64url JSON array) and `PCA-Narrow` in `requirePCA`.

Reference: Macaroons third-party caveats and discharge macaroons, Birgisson et al., NDSS 2014 (the paper's mechanics are cited from the paper; the publisher page fetched for this work lists only the abstract, so the section-level claim is unverified here). Biscuit's third-party blocks, https://doc.biscuitsec.org/reference/specifications (fetched): a third party signs a block without seeing the token; the holder appends it; a block can only restrict. PCA's difference: the third party signs a standalone artifact bound to a hop, not a block in a chain, so no chain mutation is needed.

## 2. Offline attenuation, `sealed` and the `narrow` block

What a holder can do offline: `attenuate`/`delegate` append a hop signed by the holder's key. Hardening, each with a test: a hop cannot drop, reorder or edit a parent caveat even with its own valid signature (prefix rule in `verifyChain`); depth 16, 256 caveats per hop, 1024 per chain; every hop is attributable (unlike Biscuit's ephemeral keys, which is a deliberate difference).

`{type:"sealed"}`: satisfied iff the hop that carries it is the leaf. A hop appended below is structurally valid but never satisfies the seal; siblings are unaffected. No members. Sealing does not stop `narrow` (it only restricts).

**narrow** (artifact, domain `atlas-pca/narrow/v1\0`): `{v:1, kind:"pca-narrow", cap_hash, holder, caveats[1..16], action_digest?, iat, not_after, nonce, sig}` signed by the leaf holder, bound to the leaf hop and (optionally) one PCActn, at most 24 h. Its caveats join the chain's. It cannot carry `envelope`, `sealed`, `budget_alloc` or `intent_session`. It protects the holder (an agent narrows itself before touching untrusted content); stripping it only gives back authority the holder chose to give up, so the verifier does not need to require it. The new `narrow` block adds no hop, so chain depth and budget nodes do not grow. Chain compaction is out of scope for this track.

## 3. `max_uses`

`{type:"max_uses", id, n:1..256, until}`. A lifetime count backed by the verifier's existing atomic replay store: use slot `i` is `consumeOnce(b64u(sha256("atlas-pca/max-uses/v1\0" + cap_hash + "\0" + id + "\0" + i)), until, now)`; the caveat takes the first free slot of `n`. Concurrent actions never share a slot and the count holds across processes when the store is shared and durable. At `now >= until` the caveat fails. Spent only after everything else allowed (and after the counter claim in `requirePCA`); a refusal after a slot is taken cannot give it back (fail closed). Cost is up to `n` store calls once the caveat is nearly spent. The store interface is the TTL'd consume-once of every replay store (`consume_once(key, retain_until, now)`: true iff no live record, remembered until `retain_until` inclusive, the longest horizon kept, a horizon before `now` or an empty key refused and nothing recorded); every native store implements it (vectors `consume_once_ttl`), so a slot expires with its caveat.

## 4. `derive`: bounded derived facts

`{type:"derive", id, defs[0..8], check}`. No general Datalog and no solver in the trusted core. Defs are evaluated in order and may refer only to earlier names (stratified, non-recursive). Kinds: `count{verb?, resource_prefix?, window_ms 1..30d}` over the verifier's own history, `param{path}` (at most 4 safe segments), `action{field: verb|resource}`, `claim{caveat_id, claim}` (only from a discharge that verified in this evaluation), `expr`. Expressions: `{ref}`, `{const}`, `eq neq lt lte gt gte`, `and`/`or` (1..8 args), `not`; depth at most 4, at most 32 nodes in total. Evaluation is Kleene three-valued: a missing fact is unknown; the check must be exactly true, so false and unknown both refuse. Ordering needs safe integers (else unknown); equality never coerces. Facts come only from the action, the verifier's history and verified discharges: an agent-supplied fact is never trusted.

## 5. Evaluation and wiring

`evaluateK1(grant, chain, k1, {now, action})` evaluates the K1 caveat types of the leaf hop's cumulative list plus a verified narrow block, and returns the narrow block's non-K1 caveats (`plain`) for the stock evaluator. `decide()`, `verifyPCActn` and `requirePCA` take it as `k1` (`pins`, `discharges`, `narrow`, `revoked_discharges`, `spiffe_id`, `history`); `requirePCA` also takes `usesStore`. A chain that carries a K1 caveat with NO K1 input at all (no `k1` configured, not even `{}`) is refused for every K1 type, including `sealed` and a constant `derive`; an empty `{}` is a configured verifier. The native verifiers follow the same rule (vectors `k1_unconfigured`). K1 types inside an `envelope` caveat remain unsatisfied. The opt-in proved policy VM (`PCA_VERIFIED_CORE=policyvm`) does not know the K1 types; K1 caveats are taken out of its input and evaluated by this module.

The presented artifacts travel in headers: `PCA-Discharges` (strict base64url of UTF-8 JSON, an array) and `PCA-Narrow` (the same, any JSON value); an empty value is absent, names are case-insensitive, unreadable text is no discharge. The guards of every native read them (`presented_k1`, vectors `k1_headers`) and merge them under the configured `k1` (the verifier's own members win).

**Composition with the proved policy VM.** The K1 types are taken out of the lists the VM sees and their verdict is conjoined as the delegated-caveat input of the proved decision kernel. `formal/dafny/K1Compose.dfy` proves the take-out loses nothing (`SplitConjunction`), that the VM refuses an unknown type if one is left in (`UnknownTypeUnsatisfied`), and that a K1 failure never releases while a pass leaves the VM's decision unchanged (`K1RefusalNeverReleases`).

**Chain compaction.** `chain-compact.ts` folds a chain into `{depth, hops_root, leaf}`, the root being a Merkle root over the ordered hop hashes. A verifier remembers a chain only through `ChainMemo.rememberVerified`, which runs `verifyChain` itself; a compact chain resolves only against that memo (depth and last hop must match) into a `ChainView` the caveat language uses in place of the full chain with identical results (all `k1_eval` vectors are replayed through it). The PCActn wire still carries `cap_chain`; a compact PCActn member would change the proved core and is out of scope.

## 6. SPIFFE

`{type:"spiffe_bound", spiffe_id | spiffe_prefix}` (exactly one). The presenting workload's SPIFFE ID must equal `spiffe_id`, or equal or lie below `spiffe_prefix` (`prefix + "/"`). The ID comes from an SVID the verifier verified and that is bound to the PCActn leaf holder (`spiffeIdForHolder` in `@atlasauth/pca-spiffe`), never from the request. A workload can be a discharge issuer: pin `{label, class:"workload", pk, spiffe_id}` (`workloadDischargePin`) and name `issuer_spiffe` in the caveat. SPIFFE ID syntax follows SPIFFE-ID.md (fetched): trust domain `[a-z0-9._-]` up to 255 bytes, path segments `[A-Za-z0-9._-]`, no empty, `.` or `..` segments, no trailing slash, no query, fragment, userinfo or port, up to 2048 bytes.

## 8. Declined

No general Datalog or solver in the core, no automatic widening from denials, no on-chain redemption, no anonymity for attenuation (attributability is a feature), no verifier call to the issuer.
