# PCA 0.5.0

0.5.0 is the maturity release. Components that were experimental move to production, the cryptographic and research components that engineering alone cannot promote move to a "hardened, awaiting independent audit" tier that says what each one is waiting for, and every safe default that used to be opt-in is now on. All packages and all nine native SDKs (Go, Rust, Swift, .NET, PHP, Ruby, Java, Kotlin, Python) ship together at 0.5.0.

## Security advisory: upgrade from 0.4.x

Releases up to and including 0.4.3 contain fail-open verifier defects. There is no 0.4.4; the fixes ship in 0.5.0. Read the full [advisory](../advisories/2026-11-pca-0.4.x.md) for impact, severity and workarounds. In short:

1. TypeScript: transparency-ledger consistency proofs built from nodes that were not 32 bytes were accepted in the default mode.
2. TypeScript: Intel DCAP / TDX collateral with a duplicate `tcbInfo` or `enclaveIdentity` member could make an out-of-date or revoked platform read as up to date.
3. TypeScript: Google Confidential Space accepted a JWK key placed beside a genuine certificate chain.
4. Python: the core verifier could allow a request after an internal fault.
5. All native SDKs: a delegation chain whose child allocated more `budget_alloc` than its parent passed, and a PCActn carrying `zk_compliance` passed the core verifier with nothing checking it.
6. TypeScript (`@atlasauth/pca`, `@atlasauth/pca-a2a`) and Go: a classical grant naming an issuer pinned in `pqPins` (Go: `VerifyOptions.PQPins`) passed the `pq_pin` check, so the pin did not stop an attacker holding the issuer's Ed25519 key. The other native SDKs had no issuer-level pin in 0.4.x and are not affected.
7. Smaller fixes: `verifyIntentRequired` now requires a clock; an accumulator declaration with an unknown aggregate is refused; five satellite packages (revocation, AP2 usage counters, web-bot-auth directory keys, connector URL variables, verification explanations) closed fail-open cases.

The 0.4.3 statement that no forged evidence was accepted does not hold for items 1 to 3.

## Breaking changes and safer defaults

Most of these are defaults that flipped to the safe value. The migration guide has the exact options, and each has an explicit opt-out you should treat as a bridge only.

- **Policy plane (native SDKs).** Lease, break-glass and blueprint state constructors now REQUIRE a durable key-value store; a process-local store exists only as an explicitly named `Memory*` kv (TypeScript parity). There is no no-argument constructor. `multiInstance` rejects a process-scoped replay store. A bare native guard or `Authorize` with no plan configured denies `plan_root_authorized` unless the host sets the plan to `single-step` explicitly (`Protect` keeps single-step, as in TypeScript); an unknown root never falls back to single-step. The core verifier requires `authorizedPlanRoots` or the explicit `insecureSkipPlanRootCheck`. The full risk score, trust budget, threshold step-up and caution floor are enforced natively; a signed `caution` or a `threshold` is no longer skipped.
- **RSA keys (all languages).** A public key is usable only if its modulus is 512 to 16384 bits and its exponent is odd, at least 3 and at most 32 bits; the check runs before any modular exponentiation. RSA-PSS issuer keys with parameter restrictions OpenSSL refuses are refused.
- **Size and structure caps.** OID content over 256 bytes or an arc over 64 groups, an RFC 3161 timestamp list over 8, a lenient JSON segment over 16 MiB, and RIM XML nesting over 64 are refused before any trust check.
- **Configuration typing.** A present value of the wrong type in a verifier policy is a constructor error instead of being silently dropped: NVIDIA `collateral`, `firmware`, version floors and deny lists, `requireCrlIssuers`, `leafSubjectIncludes`; Intel `policy.collateral`; non-array allowlists such as `hostData`; a non-finite MAA SVN floor.
- **Revocation epoch.** The rollback pin is automatic in the native SDKs; the host no longer has to supply it.
- **Not changed (deliberate).** The OCSP standalone options (nonce echo, `requireGood`, `maxAgeMs`) stay out of the standalone helpers; the integrated NVIDIA path does not use them and enforces its own freshness.
- **PQ pins.** An issuer with a `pqPins` entry no longer accepts classical (Ed25519) grants (`pq_pin: the grant issuer is pinned to a post-quantum key; a classical grant is refused`). Unpin the issuer if you want classical grants from it.
- **Assurance label.** `preview` is now `awaiting_audit` everywhere (reports, options, helpers, denial text). The old name is accepted as input for one release.
- **Provenance by default.** `authorize()` checks provenance. A sensitive action escalates, never allows, unless its choice and arguments derive from the principal.
- **Verifier defaults.** `verifyPCActn` requires the default checks. `requirePCA` needs an operation mapping, defaults to multi-instance state and uses an audience-scoped replay key. `authorizeToolCall` runs the full `authorize`. The plan-root check fails closed when no authorized plan is configured. `CheckStatus` gains `unsupported`, and the `counter` check is split into `counter_format` and `replay`.
- **Python Ed25519 signing needs `cryptography`.** The built-in pure-Python signer is not constant time, so signing without `cryptography` (`pip install 'atlas-pca[fast]'`) raises unless you opt in with `allow_insecure_signer` (tests and throwaway keys only). Verification is unchanged.
- **Native SDKs.** Guards and middleware use the full authorize path by default. A PCActn with `bond_ref` is denied unless allowed. The AMD root pin comes only from the processor family. Malformed allowlists and floors are refused rather than read as absent. Azure MAA, Confidential Space and NVIDIA certificate chains use the strict chain profile (non-CA intermediates, missing `keyCertSign`, exceeded path length, CA leaves and unknown critical extensions are refused).
- **NVIDIA collateral.** By default every chain certificate that names a CRL distribution point must be covered by a verified CRL from its issuer; previously any one fresh CRL satisfied the check. The new `requireCrlFor` option (`cdp` by default, `all`, or an array of chain indices) tunes it.
- **Denial reasons** name the failing limit, identically in TypeScript, Python and the nine native SDKs. The reversibility class `costly` is now `rate_limited` (the old word is accepted for one release). The `@atlasauth/pca` root no longer re-exports experimental extensions; import them from the `ext` subpaths.
- **Other packages flip safe**: gateway and agent-framework guards, OIDC requires https, DPoP replay store, WebAuthn sign counts, payments in minor units, AP2 integer terms, strict token vault, SCIM, GNAP content digest, ID-JAG strictness, transaction tokens at draft 11.
- **Wire and digest changes**: non-string tool output is hashed over canonical JSON; undo tokens use the strict JSON profile; post-quantum threshold artifacts move to v2; the action schema moves to v2; Agent Card signatures cover RFC 8785 bytes.

Upgrade steps: re-sign Agent Cards, post-quantum threshold artifacts, v1 approvals and old safety certificates; re-issue open AP2 mandates; apply the database migrations listed in the migration guide before deploying a hosted API build; if you use the optional `snarkjs` peer, override `underscore` to 1.13.8 or later.

## New in 0.5.0

- **Action definitions.** Define an action once and derive its policy, checks and documentation: a CLI (`init`, `import`, `lint`, `test`, `explain`, `diff`, `build`, `sign`, `publish`), 24 lint rules, importers for MCP, OpenAPI and JSON Schema, signed packs, evolution records and grant pins, trait floors, and the rule that an unconfirmed action is treated as maximally dangerous.
- **Undo windows.** Signed undo tokens and receipts, an `undo_window` obligation and an optional admission hook (native SDKs accept the hook).
- **Workflow and read-side authorization.** A principal signs one workflow commitment and each step is admitted only as part of it; signed read grants, redaction, read receipts and sink checks carry data labels into later write decisions.
- **Approvals and money.** Agent payment network tokens, risk-priced escalation, wallet permission mapping and checks in all nine native languages.
- **Signing what the person saw.** Rendered-action signing and a vault proxy mode; lifecycle and policy operations including shadow rollout.
- **Supply chain.** Offline Sigstore bundle verification in TypeScript and all nine native SDKs; guard authoring.
- **Caveat language v2.** Third-party discharges, `sealed`, the holder-signed `narrow` block, `max_uses`, bounded `derive` and `spiffe_bound`; signed `fresh_at`; signed agent passports; goal binding v3.
- **Protocol and identity entry points** and an optional runtime containment sandbox.
- **Formal verification.** A machine-checked security proof for `pca-abe` in the generic bilinear group model, with formal evidence sections and computational-proof entries.
- **Native SDK parity.** Each native SDK gains the authorize pipeline with an assurance report, provenance by default, undo windows, one-call `protect` where the framework allows, `explain_refusal`, agent-side signing (keys, grant minting, delegation, PCActn building), attestation verifiers (AMD, Intel, Azure MAA, Confidential Space, NVIDIA including OCSP and RIM), operational-plane artifacts, ledger, mesh, optimistic and intent-history modules, blueprints, leases, plan lifecycle and operations, and shared-vector conformance.
- **Agents in every language.** An agent written in Go, Rust, Python, Java, Kotlin, .NET, PHP, Ruby or Swift no longer needs a TypeScript helper to sign. Each language has the one-call agent facade (plain-language limits compiled against the built-in connector catalog into a signed root grant), `act`, `dry_run`, sub-agents, delegation, seeded deterministic keys, the other principal and agent signers, and post-quantum signing for every suite it verifies (LESS signs in TypeScript only; FN-DSA in TypeScript and Rust). Native output is compared byte for byte with shared producer vectors and every native-signed proof is verified by the TypeScript reference in CI. See the language parity page for the per-language names and exceptions.
- **Release process.** Provenance-attested publishes, an SBOM per repository and a security-evidence report per release.

## Notable fixes

- **NVIDIA OCSP.** A valid response was refused every time when the CA's key hash, nonce or signature bytes happened to read as a malformed time (about 4 in 65,536 key hashes). The time check no longer looks inside octet and bit strings; times in the surrounding structure are still checked. Fixed in TypeScript, Go and Rust; the other languages never had the problem.
- **.NET.** Intel PCS dates with fractional seconds were refused; they now parse as they do in TypeScript.
- A mesh head pinned at size 0 can advance; a provenance label cut no longer splits a surrogate pair; a dismissal reason made only of U+001C to U+001F is blank; non-sum accumulators no longer refuse large sums.
- **Sigstore.** The reported Rekor log index is always the verified index.

## Known differences between languages

The shared conformance vectors pass in every language. These behaviours still differ, and none weakens a check.

- **Number printing.** Rust prints integers outside the safe range (beyond 2^53, up to the full 64-bit range) exactly, where TypeScript prints the nearest double. This affects lenient canonical JSON only and matters only for documents carrying such numbers; keep values within the safe integer range if you compare digests across languages.
- **Obligations.** Go, .NET and PHP read a language null as an absent list, while TypeScript denies a JSON null. Refuse a present JSON null before calling them. Those SDKs refuse a signed PCActn carrying obligations as an unknown field.
- **Verb floors.** Go refuses a numeric-string floor such as `"3"` that TypeScript coerces (stricter). PHP drops a one-element array floor such as `[5]` that JavaScript coerces to 5.
- **Lease revocation.** Java, Python and PHP do not prune expired revocations from the in-memory registry (it has no clock); Go does. The effect is memory growth only.
- **Undo.** The native SDKs have no undo store or coordinator, only the admission hook. Swift's provenance recorder records string content only. Swift `protect` has no catalog-priced limits and Kotlin has no catalog risk. Go's authorize does not port the `beacon` check.
- **Kotlin** saturates an enormous NVIDIA RIM index, which can only refuse as a false duplicate; TypeScript has no upper bound there.
- **Conformance layers.** `policy-vectors` are report-only for the native SDKs and `stateful-vectors` run in TypeScript only.
