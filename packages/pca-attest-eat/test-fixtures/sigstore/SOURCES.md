- `trusted_root.json`: the Sigstore public-good trusted root, `targets/trusted_root.json` of sigstore/root-signing at commit f39569f398fa958b314611e75c637c8d92e6bd4f (https://raw.githubusercontent.com/sigstore/root-signing/main/targets/trusted_root.json). - `npm-sigstore-5.0.0.attestations.json`: the npm registry attestations of `sigstore@5.0.0` (https://registry.npmjs.org/-/npm/v1/attestations/sigstore@5.0.0): a v0.3 bundle with SLSA v1 provenance (GitHub-hosted runner, keyless Fulcio certificate, Rekor v1 `dsse` entry with inclusion proof, checkpoint and SET) and a v0.2 npm publish attestation signed with a public key (not keyless; the verifier refuses it). The provenance subject is the sha512 of https://registry.npmjs.org/sigstore/-/sigstore-5.0.0.tgz (`integrity` sha512-hJqJfoG/e4qFQaauQL00c6J6FrHLBGKtkFvW3JbTSIEFOhLrSjdSM/gWd/yUOfYo/gsERehTXGC1VZWX+9X4Dg==).
- `conformance/<case>/`: the DSSE cases of sigstore/sigstore-conformance at commit acb38c9ee4274fa058127e6a5a4cdb9e94e449e1, `test/assets/bundle-verify/<case>/` (bundle, trusted root when the case ships one, README), unmodified. Cases ending in `_fail` must be refused. Cases without a trusted root use the public-good root above. The `rekor2-*` cases are Rekor v2 (hashedrekord 0.0.2 over DSSE, RFC 3161 time) on the Sigstore staging instance; `intoto-with-custom-trust-root` has both a SET and an RFC 3161 timestamp.
- `synthetic/`: minted once by `scripts/mint-synthetic-sigstore.ts` (a private test root, intermediate, CT log key, Rekor-v1-like log key and timestamp authority; no private key is kept). Bundles in which every check passes except exactly one: the DSSE signature, the embedded SCT, or the Authority/Subject Key Identifier link; plus a fully valid control.
