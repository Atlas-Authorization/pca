# Changelog

See the full release notes in [docs/pca/CHANGELOG.md](https://github.com/Atlas-Authorization/pca/blob/main/docs/pca/CHANGELOG.md).

## 0.4.0 - 2026-10-11

Lockstep release; see the 0.4.0 entry in the full release notes for the summary of breaking changes (deriveDecideInput needs ctx.grant, frostAggregate needs verificationShares, decide() no longer guesses the plan node, durable-state fence format, regex work budget). Details for this package:

Fixed (durable-state, R6-CORE-01..03): operator recovery of a PAUSED holder is safe by construction (lock re-check before the journal AND head renames; lock generation in every record and the head; recovery takes the lock, writes a `state.fence` cut, then frees it; late records from a fenced generation are refused on load, a stale late head is repaired). Recovery's liveness check keys on the PID namespace, not the hostname. New `legacyLock: true` for a legacy single-file `state.lock`; incomplete top lock records are released with `expectedHolder: 'unreadable'`. One-way format change: older versions cannot open a directory written by this one.

Fixed (durable-state, R6-CORE-01 follow-up): an operator recovery that is itself killed midway can no longer let the released (paused) holder's late journal in. Its lock (`recovering`) now also records `start`/`boot`; a same-namespace waiter that takes over a dead lock marked `recovering` carries the mark on and cuts + fences under its own generation before loading (before, the takeover wrote no fence, so a recovery killed between taking the lock and writing `state.fence` left the paused holder unfenced). Fences are now append-only: each is its own immutable file `state.fence.<gen>-<random>` (the `state.fence` list is still read; quarantine writes its genesis fence there and moves old fence files aside), so a fence writer paused between reading and renaming a shared list can no longer drop a fence written meanwhile. Test-only crash hook `PCA_DURABLE_TEST_RECOVER_CRASH_AT` (NODE_ENV=test only). Threat model documented: the lock and fence files are unsigned by design; automatic takeover never breaks a lock recorded under another hostname or PID namespace.

Fixed (threshold): a share that names its own `pq_pk` must name exactly the key its role registers. A different key (even with signatures valid under the registered key), a non-string value, or a `pq_pk` on a share for a role that registers none is refused with the new reason `share for role <r> names a pq_pk that is not the key its role registers` (verified core: `Threshold.dfy` `PqPkMismatch`). The Python, Go, Rust, Java, Kotlin, .NET, PHP, Ruby and Swift verifiers apply the same rule to every suite; new DENY vectors `r6-neg-*-pq_pk-*` in `threshold_set`.

Suite policy defaults documented: no list = no restriction, an empty list refuses everything, and the hosted API defaults to ed25519 + Ed25519 hybrids (README lists the exact list to pass offline).

Fixed: `createPqSoftwareVerifier` treated `allowedSuites: []` as no restriction; it now refuses every suite (undefined keeps meaning no policy; a non-array policy fails closed), matching the core verifiers.

`verifyPCActnCore`, `verifyPCActn` and `enforceRequired` now delegate their decisions (check fold, audience, validity window, `grant_ref_bound`, counter, leaf, hook / zk / attestation-gate rules, F-1 threshold rule, final `allow`, required-check enforcement) to `@atlasauth/pca-verified-core`, the Dafny-proved decision core (see docs/pca/security/verified-core.md). Behaviour is identical on the full conformance corpus except one fail-closed fix: a NaN / non-integer verifier clock (`nowEpoch`) now fails the `validity` check; previously NaN made an expired PCActn pass `validity`.

`verifyChain` (capability.ts), `verifyThreshold` (threshold.ts) and `guardPCActnReplay` (replay.ts) now also run the Dafny-proved decision code: the chain walk, depth bound and caveat-prefix attenuation (`Chain.dfy`), the F-2 PQ-binding / F-4 suite-policy rules, the threshold distinct-role count and signer-set validation (`Threshold.dfy`), and the replay-guard decision order with consume-once (`Replay.dfy`). Primitive evaluation (parsing, hashing, signature verification) stays in TypeScript. Public behaviour is byte-identical (verdicts, reasons, store calls), checked by differential tests against frozen pre-wiring copies. New CI gate: `scripts/check-verified-core.sh`.

Security fixes from the Dafny extension audit (docs/pca/security/verified-core.md), each with a regression in `src/verified-core-findings.test.ts`:

- BREAKING `memoryNonceStore(max)`: a consumed nonce is never re-accepted inside its retention window. A full store now REFUSES new nonces (fail closed) instead of evicting the oldest (which re-opened replay); entries age out only after `retentionMs` (default 1 h; new second argument `{ retentionMs, now }`). `max < 1` or a non-integer now throws `TypeError` (`max = 0` gave no replay protection at all). Clocks are integer epoch ms: a non-integer `retentionMs` throws `TypeError`, and a clock reading that is not a safe integer (fractional, NaN, Infinity) refuses the nonce (fail closed, nothing recorded); this matches the Dafny-proved store exactly.
- BREAKING `verifyAllowlistManifest` / `verifyAllowlistAnchored`: a non-finite or non-number `clockSkewMs`, `maxLifetimeMs`, `maxHeadAgeMs`, or a non-integer `minVersion` / `lastSeenVersion` is refused (`malformed` / `bad-head`) instead of silently disabling the window / version checks (`NaN` / `Infinity` skew verified EXPIRED and NOT-YET-VALID manifests and stale / future tree heads).
- `verifyAllowlistDurable`: versions are append-only. A same-version / different-digest write (racing writer) is a `conflict` and no longer overwrites the stored high-water mark.
- `createMultiRootVerifier`: a `null` / `undefined` / non-object result from one root verifier is a FAILED root (skipped, or a denial if the root is `required`) instead of aborting the whole N-of-M check.
- BREAKING `verifyLedgerConsistency` (RFC 9162): `oldSize = 0` now requires `oldRoot` to be the empty-tree root (`EMPTY_TREE_ROOT`, newly exported) with an empty path (and `newSize = 0` requires the empty root again); previously any `oldRoot` / `newRoot` was "consistent" from size 0. The index arithmetic is BigInt (it used 32-bit `>>`, `&`, so `(3, 7)` and `(3 + 2^32, 7 + 2^32)` verified the same proof); sizes must be safe integers and the path is bounded. Heads for an empty log must carry `ledgerRootOf([])` as root.
- Taint: label kinds and registry kinds are own-property lookups (`constructor`, `__proto__`, ... gave `NaN` taint, which passed `enforce.taint` at `maxTaint: 0`); an unknown kind ranks as the worst level; `computeTaint` really never throws (sparse `trusted_refs`, a throwing `registry.lookup` or hostile getter yield `{ valid: false, taint: 1 }`); the `enforce.taint` gate fails closed on a non-finite taint.
- `compareUtf8` breaks ties between byte-equal but different strings (lone surrogates all encode as U+FFFD) by UTF-16 code-unit order, so canonical key order (and `eq` / `in` in the predicate DSL) no longer depends on insertion order for such keys.
- `reversibility_max` (predicates.ts, agent-native.ts) requires `class` and the context class to be strings (no `String()` coercion of arrays / objects).
- Own-property lookups also for `parseLimit` periods (`$5/constructor` yielded a function period), policy template names, the OCSP hash-OID table, and `canonicalAction` parameter keys (`constructor` threw a spurious duplicate-key error and a `__proto__` parameter was dropped from the canonical form).
- Intel TDX DER length reader: a 4-byte length >= 2^31 no longer goes negative through a 32-bit shift.

## 0.3.0

Lockstep release of the whole family. 0.2.0 is superseded. Breaking: `@atlasauth/pca-scitt` leaf format (RFC 9162), `@atlasauth/pca-vdf` `setup` renamed `insecureDevSetup`, `stark-pca` / `stark-pca-plonky3` public-input layout (full 256-bit commitments). Security fixes: VDF zero-work forgery, non-canonical Ed25519 points (mpc-wasm), OPRF scalar malleability, CIBA guessable request id, Envoy query-string deny. See the link above for the full list and migration notes. This package itself has no API change.

## 0.2.0 (superseded by 0.3.0)

Breaking: the resource-server verifier (`requirePCA` and verdict computation) now lives in this package; new mandatory `grant_ref_bound` check; AMD SEV-SNP weights slot and the synthetic attestation profiles removed. Added: real AMD SEV-SNP, Intel TDX/DCAP, NVIDIA GPU, Azure MAA and GCP Confidential Space attestation roots, signed allowlists, PQ quorum certificates, the replay-store contract and FN-DSA suites. See the link above for the full list.
